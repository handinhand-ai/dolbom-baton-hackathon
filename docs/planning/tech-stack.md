# 기술 스택 — 목표와 검증 상태

이 문서는 **해커톤 목표 스택**을 기록하며, 현재 기본 스켈레톤에 해당 기술이 설치·연동됐다는 의미는 아닙니다.

| 영역 | 검토 중인 목표 | 현재 시작본 |
| --- | --- | --- |
| 프론트엔드 | React + TypeScript + Vite, 모바일 우선 | 기본 HTML·CSS·JavaScript만 포함 |
| 개발용 서버 | Node.js 22 | 기본 HTTP 서버 포함 |
| 배포 | Vercel 검토 | 미연결·미배포 |
| AI 호출 | 서버 측 프록시, 비밀 키는 환경변수로 관리 | 미구현 |
| 음성 인식 | OpenAI 음성 받아쓰기 등 기존 모델 검토 | 미구현 |
| 구조화·질문 답변 | 구조화 출력과 근거 검증 | 미구현 |
| 녹음 | 브라우저 MediaRecorder, 모바일 브라우저 호환성 검증 | 미구현 |
| 저장 | 해커톤 시연용 브라우저 저장 또는 별도 백엔드 검토 | 미구현 |
| 공유 | 선택 항목만 권한·기간 검증 후 접근 | 미구현 |
| UI 글꼴 | Pretendard 검토 | 기본 웹 스타일 사용 |

## 기술 선택의 유의 사항

- 모델 이름과 실제 제공 여부, API·음성 형식·브라우저 호환성은 개발 환경에서 검증하기 전까지 미확정입니다.
- 6자리 코드만으로 암호화된 기록을 보호하는 클라이언트 공유 방식은 오프라인 추측에 취약할 수 있어 실제 민감한 돌봄 데이터에 적용하지 않습니다. 프로덕션 수준의 접근 통제는 별도 설계가 필요합니다.
- 운영 측면에서 개인정보 보존, 철회·만료, 서비스 장애 및 키 유출 대응을 추가 검토합니다.
- 유료 외부 API 활용이 허용되더라도 비용 발생 여부와 소유자의 승인을 확인하기 전에는 과금 리소스를 만들거나 유료 호출을 실행하지 않습니다.
- 서비스 방향이 유지되는 한 API 또는 ERD 변경은 가능하되 기존 데이터 계약과 팀원의 변경 사항을 함께 확인합니다.
