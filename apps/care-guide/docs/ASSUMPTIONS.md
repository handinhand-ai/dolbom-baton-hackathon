## 1. 저장소 현황

| 항목 | 확인 결과 | 적용 |
|---|---|---|
| 코드 | 기능 3 코드 없음 | `apps/care-guide/` 아래에 새로 작성 |
| 기존 서버 | API 명세는 "Node 22 기본 HTTP 서버 골격, `/api/health`만 구현"이라고 적었으나 실제 파일은 없음 | 처음에는 그 방식으로 만들었으나, 2026-11-21 요청에 따라 **사전 산출물 기술 스택(Next.js + TypeScript · PWA · Vercel · OpenAI)**으로 옮김. API 경로·오류 형식은 API 명세대로 유지. `/api/health`는 `{status, mode}` 형태이고 `mode`에는 DB 모드를 넣음 |

## 5. 안전 원칙 구현 방식

- **근거 범위**: 검색 SQL 함수가 권한을 먼저 확인하고, 대상자·허용 카테고리 안의 공식 가이드와 확인 기록만 반환합니다.
- **사실·기록·가이드·제안 구분**: 화면의 각 안내 문장에 `공식 가이드 근거 / 과거 기록 근거 / 일반 안내 · 개인 근거 없음 / 기록 없음 / 안전 안내` 라벨을 붙이고, 근거 번호·작성일을 연결합니다.
- **AI 결과 검증**: 근거 목록에 없는 ID는 버립니다. 근거 없이 "기록 기반"이라고 한 문장은 일반 안내로 낮춥니다. 근거가 없으면 비교 상태를 `비교할 기록 없음`으로 강제합니다. 의료 지시 표현(처방, 용량, mg 등)은 안전 문구로 바꿉니다.
- **규칙 기반 모드**: 입력에 쓰인 표현만 뽑습니다. 원인·의도·차이를 추정하는 규칙은 없습니다. 안내는 새 문장을 만들지 않고 근거 원문을 그대로 보여줍니다.
- **기록 충돌**: 같은 대상(예: 헤드폰)에 대해 긍정 결과와 부정 결과가 함께 있으면 양쪽을 `contradicts`로 표시합니다. 어느 쪽이 맞는지는 정하지 않습니다.
- **기록 저장**: AI 후보는 `care_record_draft`에만 있습니다. 종사자가 확인(`reviewed=true`)하지 않으면 서버가 409 `REVIEW_REQUIRED`로 저장을 거부합니다. 저장해도 `care_guide_item`은 바뀌지 않습니다.
- **음성**: 인식 결과를 입력창에 넣기만 하고 자동 분석하지 않습니다. 서버는 `voice_transcribed` 입력에 `transcriptConfirmed=true`를 요구합니다. 원본 음성은 저장하지 않습니다.

## 6. Next.js·Vercel 전환에서 정한 것

| 항목 | 적용 |
|---|---|
| 서버 로직 | 기존 검증 로직(권한, 하이브리드 검색, 근거 검증, 확인 후 저장, 승인 분리)을 TypeScript로 옮겨 `src/lib`에 두고, Next.js API 라우트(Node 런타임)에서 호출 |
| 인증 | 이전과 같음. 실제 인증 없이 `DEMO_STAFF_ID`를 현재 종사자로 사용 |
| Vercel에서 DB 키가 없을 때 | 메모리 PGlite로 시작하면서 합성 데이터를 넣음. 저장 내용은 인스턴스가 바뀌면 사라지며, 화면 띠에 "재시작하면 초기화"로 표시 |
| 받아쓰기 | OpenAI 키가 있으면 서버 받아쓰기(녹음 → 전송 → 텍스트, 음성 미저장, 최대 4MB). 없으면 브라우저 음성 인식. 받아쓴 글은 항상 확인한 뒤에 보냄 |
| PWA | 홈 화면 설치용 manifest·아이콘·서비스 워커. 대상자 데이터(API 응답)는 기기에 캐시하지 않음. 오프라인이면 안내 문구만 표시 |
| 미구현 | 파이프라인의 비식별화 단계, 사용자 인증, 대화 이력 보관 기간 정책 |
